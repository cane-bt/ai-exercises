# ADR 0001: Cursor と Claude Code を作業の種類で使い分ける

- ステータス: 採用
- 日付: 2026-10-24

## コンテキスト

AI を使って業務の自動化と、副業の実績になるアプリ開発を進めている。AI コーディングツールとして Cursor と Claude Code の両方を使えるが、どちらで何をするかが決まっていない。そのため、次のことが起きやすい。

- 小さな修正をまとめて任せて、変更内容を追えなくなる
- 大きな作業をエディタで少しずつ進めて、時間がかかる
- 両方で同じファイルを触り、変更がぶつかる
- AI が書いたコードを説明できないまま使ってしまう（副業の案件では説明責任がある）

## 決定

作業を「自分がコードを一行ずつ見ながら進めたいか、結果だけ見て判断したいか」で分け、ツールを選ぶ。

| 作業 | 使うツール |
| --- | --- |
| 複数ファイルにまたがる機能追加・バグ修正 | Claude Code |
| コマンド実行・テスト・確認までを一続きでやる作業 | Claude Code |
| フォルダ作成やファイル整理など、コード以外の作業 | Claude Code |
| 開いているファイルの部分的な修正、文言・見た目の微調整 | Cursor |
| コードを読みながらの質問、補完を受けて自分で書く練習 | Cursor |

運用のルール:

1. 大きく作るのは Claude Code、仕上げの細かい修正は Cursor で行う。
2. Claude Code が書いたコードは Cursor で読み、「なぜこの構成か」を質問して自分の言葉で説明できるようにする。
3. Claude Code に任せる前に、目的・使う人・やってほしくないことを言葉にして伝える。
4. 同じファイルを両方のツールで同時に編集しない。
5. 大きな変更を任せる前に git でコミットし、すぐ戻せるようにする。

## 結果

良くなること:

- 大きな作業は速く進み、細かい修正は自分の手で確かめながら進められる。
- コードを読んで質問する手順が入るので、抽象化と具体化の練習になり、案件で説明できる状態を保てる。
- コミットで区切るので、AI の変更が気に入らなくても戻せる。

気をつけること:

- 2つのツールを行き来するぶん、切り替えの手間がかかる。
- git で管理していることが前提になる。この作業フォルダ（`ai_exercises`）はまだ git リポジトリではないため、ルール5を守るには先に `git init` が必要。
- 両ツールとも機能の更新が速いので、向き不向きは変わりうる。大きな変化があればこの ADR を見直し、新しい ADR で置き換える。

## 検討した代替案

- **Claude Code だけを使う**: 速いが、コードを読む機会が減り、説明できないコードが増えやすい。
- **Cursor だけを使う**: 理解しながら進められるが、複数ファイルにまたがる作業や、実行・テストまで含む作業に時間がかかる。
